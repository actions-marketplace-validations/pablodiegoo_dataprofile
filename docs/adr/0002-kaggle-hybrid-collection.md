# Hybrid Kaggle collection using headless Chrome DOM inspection across progression tracks and optional REST API v1

Kaggle's official REST API v1 (`/api/v1/kernels/list` and `/api/v1/datasets/list`) exposes artifact metadata and raw `totalVotes` (which include non-qualifying Novice upvotes), but does not expose awarded medal tiers (`Gold`, `Silver`, `Bronze`), global rankings, or progression standing across the three active Progression Tracks (`Code`, `Datasets`, and `Competitions`), while plain HTTP requests to public profile pages are blocked by Google reCAPTCHA challenges. Furthermore, Kaggle's main profile page (`/<username>`) omits tracks that are still at the `Kaggler` tier (pre-`Expert`) and encodes medals and tiers as `<img>` `alt`/`title` attributes rather than plain text. Given these constraints, we implemented a hybrid collector that uses headless Chrome to inspect the main profile and track sub-pages (`/<username>/code`, `/<username>/datasets`, `/<username>/competitions`) while preserving `<img>` semantic attributes as the ground truth for awarded medals, tiers, ranks, and public artifact counts, and enriches artifact counts (including private work when authenticated as the Subject) through the official Kaggle REST API v1 whenever `KAGGLE_KEY` is configured.
